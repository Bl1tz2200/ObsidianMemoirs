# Call Stack
Основной поток в Node называют call stack, именно в него сыпятся все функции (по принципу: Последним зашла, первой выходишь)

Основной поток сразу будет выполнять синхронные события, а асинхронные он предоставит циклу событий (вследствие этого все синхронные события выполнятся раньше асинхронных)
## Event loop
*Цикл событий* (Event loop) - механизм, позволяющий выполнять не блокирующие (асинхронные) операции ввода вывода

Библиотека libuv отвечает за I/O события, она встроена в Node (буквально его основа), позволяет выполнять операции обращения к чему-либо асинхронно, без блокировки основного цикла событий (По факту она управляет циклом событий, о котором скажу ниже)

# Цикл событий
Теперь по подробнее про работу асинхронных операций через цикл событий:
- Приложение запрашивает операцию ввода/вывода у демультиплексера событий, в котором указывается ресурс, операция и обработчик (при этом демультиплексер сразу после принятия возвращает управление приложение чтобы оно могло запросить ещё один ввод/вывод)
- Демультиплексер передает операции в очередь событий, в котором указывает событие и обработчик (в случае Node обработчик - просто callback)
- После выполнения события, обработчик вернет callback, который цикл событий предоставит в обработчик приложения
- У Цикла есть приоритеты выполнения различных запросов (промисы будут выполнены первыми, затем таймеры и тд)

Можно сравнить с коробкой, в которую мы друг на друга скидываем функции, а потом берем сверху (первой выполнится последняя функция, второй предпоследняя, последней первая)

# Браузерный JS
Браузерный JS имеет чутка другой *цикл событий*: он делится на microtask (очередь событий) и macrotask (очередь задач) очереди, в которые из call stack (основной поток), через web api будут распределяться асинхронные задачи

Выполняются они в таком порядке: сначала выполняется синхронное событие (что не требует ожидания), потом микротаски (все), после макротаски (по одному). По одному подразумевает, что если макротаск создаст микротаски, то сначала они все будут выполнены, а только потом пойдет выполнение следующего микротаска
