# Router
У NextJS есть свой router, который работает так: чтобы указать новую страницу достаточно просто создать папку страницы в *src/app* (например src/app/prod) и в неё засунуть *page.tsx* (ну или jsx, если без TS). Ещё можно в названии папки указать `[slug]` для того, чтобы вытаскивать идентификатор страницы:

```
"use client" // По стандарту мы используем сервер, но сейчас указали именно так, чтобы код исполнялся на стороне клиента в браузере

import { useParams } from "next/navigation"

export default function Page() {
    const params = useParams<{slug:string}>() // Вытаскиваем параметры страницы
    return (<div>{params.slug}</div>) // Вытаскиваем конкретно идентификатор
}
```

Пример работы: /products/100
На странице: 100

# Хуки
Перейдем к хукам:

- хук `useRouter()` позволяет манипулировать переадресациями на странице (например можно переадресовывать на slug с обычной). Пример:
```
const {push} = useRouter()
push("/products/1")
```

- хук `usePathname()` показывает текущий путь страницы

- хук `useSearchParams()` для получения доступа к Query запроса

- хук `useParams()` для получения slug

# Клиентская/серверная стороны
Ранее я указывал `"use client"` для выполнения кода на клиентской стороне

По стандарту код использует `"use server"` и весь основной код работает на сервере

Лучше всего пытаться выносить статику на сервер (ISR (Incremental Static Regeneration (обновляемая статика)), SSG (Static Site Generation (не обновляемая статика))), ведь если использовать SSR (Server-Side Rendering (активный перерендер с постоянными запросами страницы на сервер)) - постоянные запросы на сервер - сервер просто упадет при большом наплыве народа

Серверные компоненты обычно используются для создания безопасности и прямой связи с бекендом

Для создания SSG нужно в fetch указать `cache: "force-cache"`, тогда статика закешируется при билдинге и она не будет обновляться:

```
const response = async fetch("url", {
	cache: "force-cache"
})
```

Для создания ISR нужно ещё и добавить `revalidate` (через сколько статика обновится в сек):

```
const response = async fetch("url", {
	cache: "force-cache",
	next: {
		revalidate: 3600
	}
})
```

Так же можно просто указать:
```
export const revalidate = 3600
```
Тогда не придется указывать это в фетче (в таком случае оно будет работать и в axios и в apollo)

## middleware
Существует в Next такая функция, как `middleware`, она срабатывает автоматически после того, как открывают страницу, заданную в *config*
Например:

```
export function middleware(request: NextRequest) {
	return NextResponse.redirect(new URL('/home', request.url))
}

export const config = {
	matcher: ['/about/:path*', '/dashboard/:path*'],
}
```

Это часто используется при авторизации: например, редиректит тех, кто не зарегистрирован и тд

В файле *next.config* можно указать параметры, например переменные окружения и тд (там много функций). Так же в конфиге можно указать экспериментальную оптимизацию модулей для более быстрой работы сайта
