NestJS - фреймворк для NodeJS

Основной принцип NestJS в том, что он использует множество декораторов для описания действий на странице. Все в Nest работает через классы и декораторы!!!
# Файловая структура
В папке *src* имеет 4 основных файла:
- *main.ts* - на каком порту и с какими параметрами запустится сервер
- *app.service.ts* - тут прописываем сервисы
- *app.module.ts* - тут прописываем подключение модулей
- *app.controller.ts* - тут прописываем роуты (за роуты отвечает контроллер, поэтому так назван)
# Модули
Модулями называют все, что подключается для запуска страницы (контроллер, сервисы)
Если привести пример, то *app.modules* это материнская плата, куда мы подключаем блоки
## Контроллер
Контроллер конкретно управляет данными: обычно он их валидирует и перенаправляет на сервис, который отдает ответ обратно контроллеру, а он пользователю
Главное помнить: вся логика в сервисах, контроллер нужен лишь для валидации и приема/передачи данных
## Guard
Есть и блок `Guard`, позволяющий настраивать защиту для сайта (например не выдавать данные без токена)

Для валидации данных необходимо указать DTO (data transfer object), нужно просто создать ts файл и прописать в нем то, что должно приходить в параметрах:

```
import { IsString } from "class-validator";

export class TaskDto {
    @IsString()
    name: string
}
```

Так же, для работы валидации необходимо прописать ValidationPipe на уровне контроллера:
```
  @Post() // тип запроса
  @UsePipes(new ValidationPipe()) // Создаем валидацию 
  async create(@Body() dto: TaskDto) { // Вытаскиваем параметр из ссылки сайта
    return this.taskService.create(dto)
  }
```
